Windows Login Monitor

Reads login events from the Windows Security log every hour, counts them per day for each event ID, and shows the result on a Streamlit dashboard where you pick the event ID from a dropdown.

Python 3.14 pywin32 Task Scheduler Supabase Streamlit Cloud

Setup checklist

Tick each step as you go. Your progress is saved in this browser.

0 of 7 done

  1. Open an Administrator terminal so the packages go into Program Files, where SYSTEM can find them.

    cd /d d:\NJ2026\python\windows-login-monitor\windows-login-monitor
"C:\Program Files\Python314\python.exe" -m pip install --ignore-installed -r requirements.txt

  2. In Supabase, open SQL Editor, paste supabase_schema.sql and run it. The full script is in Supabase table.

  3. Copy .env.example to .env and use the secret key.

    SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=sb_secret_...

  4. In the Administrator terminal:

    python collector.py

    You should see Step 1 to Step 5 and --- Done ---.

  5. Right-click setup_task_scheduler.bat and choose Run as administrator. Details are in Task Scheduler.

  6. Open output\collector_log.txt. The latest entry should end with Step 5: uploaded 63 rows and --- Done ---.

  7. streamlit run dashboard.py

    It opens at localhost:8501. Pick your machine and an event ID in the sidebar.

Task Scheduler

The task is called WindowsLoginMonitor. It runs run_collector.bat every hour as SYSTEM with the highest privileges, so it works even when nobody is logged in and can read the protected Security log.

The command that creates it

schtasks /Create /TN "WindowsLoginMonitor" /TR "\"%~dp0run_collector.bat\"" /SC HOURLY /RU SYSTEM /RL HIGHEST /F

run_collector.bat

SYSTEM can't see your user PATH, so the script uses the full Python path. The quotes around "PYTHON=..." stop a stray trailing space from breaking it.

cd /d "%~dp0"
set "PYTHON=C:\Program Files\Python314\python.exe"
if not exist output mkdir output
echo ===== Task run %date% %time% ===== >> output\collector_log.txt
"%PYTHON%" collector.py >> output\collector_log.txt 2>&1

Dashboard & deployment

GitHub only stores the code. Streamlit Cloud runs dashboard.py from your repo and reads the data from Supabase. The collector keeps running on your PC because it needs your PC's event log.

Push to GitHub

git init
git add .
git status

Check that .env is not listed before you commit. It holds your secret key.

git commit -m "Windows login monitor"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/windows-login-monitor.git
git push -u origin main

Deploy on Streamlit Cloud

At share.streamlit.io, create an app from your repo with dashboard.py as the main file. Under Advanced settings, choose a Python version and add these Secrets, using the publishable key:

SUPABASE_URL = "https://your-project.supabase.co"
SUPABASE_KEY = "sb_publishable_..."

The dashboard caches data for 5 minutes. Use Refresh data in the sidebar to load new numbers straight away.

Supabase table

One row per machine, event ID and day. The unique constraint is what lets the collector upsert instead of inserting duplicates.

create table if not exists login_event_counts (
    id            bigint generated always as identity primary key,
    machine_name  text        not null,
    event_id      integer     not null,
    event_name    text,
    event_date    date        not null,
    count         integer     not null default 0,
    collected_at  timestamptz not null default now(),
    unique (machine_name, event_id, event_date)
);

grant select, insert, update on public.login_event_counts to service_role;
grant select on public.login_event_counts to anon;

alter table login_event_counts enable row level security;

drop policy if exists "Dashboard can read counts" on login_event_counts;
create policy "Dashboard can read counts"
    on login_event_counts for select to anon using (true);

The secret key uses the service_role role and the publishable key uses the anon role, which is why the grants name them that way.

Troubleshooting

Follow the chart from the top to find where a run is failing.

flowchart TD
  A["Run python collector.py"] --> B{"Did Step 1 work?"}
  B -- "Could not open the Security log" --> B1["Use an Administrator terminal"]
  B -- Yes --> C{"Did Step 5 work?"}
  C -- "42501 permission denied" --> C1["Run the two GRANT lines"]
  C -- Yes --> D{"Does the task log end with Done?"}
  D -- "cannot find the path specified" --> D1["Fix the PYTHON path in run_collector.bat"]
  D -- "No module named ..." --> D2["Reinstall packages as Administrator"]
  D -- Yes --> E["Open the dashboard"]
permission denied for table login_event_counts (42501)

The table exists but the role behind your key isn't allowed to use it. Newer Supabase projects don't add these grants automatically. Run only these two lines in the SQL Editor:

grant select, insert, update on public.login_event_counts to service_role;
grant select on public.login_event_counts to anon;
policy "Dashboard can read counts" already exists (42710)

The whole schema file was run a second time. Supabase stops at the first error, so anything after it never ran. Run only the lines you still need, or use the updated schema file that drops the policy first.

Task log says The system cannot find the path specified

The Python path in run_collector.bat is wrong, often because of a space at the end of the line. Use set "PYTHON=C:\Program Files\Python314\python.exe" with the quotes around the whole assignment. Don't use the WindowsApps path; it is a Store shortcut that SYSTEM can't run.

Task log says No module named 'packaging' (or another module)

The packages were installed in your personal folder, which SYSTEM can't see. Reinstall them into Program Files from an Administrator terminal:

"C:\Program Files\Python314\python.exe" -m pip install --ignore-installed -r requirements.txt
Events 4800 and 4801 always show 0

Lock and unlock events are only logged when this audit category is turned on:

auditpol /set /subcategory:"Other Logon/Logoff Events" /success:enable /failure:enable
Dashboard says there's no data yet

Check that rows exist in Supabase Table Editor. If they do, make sure the dashboard's key is the publishable key and that the grant select ... to anon line has been run.

Security notes

The secret key can change or delete everything in your project, so it lives only in .env on the Windows PC. The dashboard gets the publishable key, which the grants and the RLS policy limit to reading this one table.

Only daily totals leave the PC. The raw file with usernames, events_raw.csv, stays in the local output folder, which is excluded from Git.

The task runs as SYSTEM because the Security log needs administrator rights. Keep the project folder somewhere only administrators can edit, since anything in run_collector.bat would also run as SYSTEM.
